2. Methods
Overview
We developed an automated pipeline for reconstructing drug-development trajectories from public clinical trial registries and computing phase-transition success rates stratified by drug modality and therapeutic area. The pipeline executes five sequential stages: (1) trial ingestion from a structured registry mirror, (2) matching and deduplication of trials into unique drug-indication candidates, (3a) modality and disease area classification and (3b) outcome adjudication, (4) funnel aggregation of phase-transition rates, and (5) automated report generation. Stages 3a and 3b share a common knowledge cache and run in parallel. Outcome adjudication has two interchangeable back-ends that emit the same output schema: a direct LLM adjudicator (llm_direct) and an FDA-timeline adjudicator (fda_timeline) that reconstructs per-drug regulatory histories from openFDA; the back-end is selected per run via the --adjudication-method flag. The report accompanying this paper was produced with llm_direct. The fundamental unit of analysis throughout the pipeline is the drug-indication candidate: a unique pairing of one drug with one clinical indication, derived from trial clustering (defined below). Definitions
A drug-indication candidate is a unique (drug, indication) pair produced by clustering raw trial records that share the same active pharmaceutical ingredient and clinical indication. Each candidate aggregates one or more clinical trial records and represents a single drug-development program for a specific therapeutic use.
A phase transition is the advancement of a candidate from one clinical or post-clinical development phase to the next (e.g., Phase 1 to Phase 2, or Phase 3 to regulatory approval). Transition rates are computed using a forward-looking cohort methodology aligned with the BIO/QLS convention, in which cohort membership (denominator) and advancement evidence (numerator) are tracked as two distinct per-candidate sets rather than a single aggregate level. For each candidate c we construct:

  • phases_observed(c) ⊆ {Phase 1, Phase 2, Phase 3, Approval, Market} — the set of phases for which there exists terminal evidence that the candidate actually reached that phase. A phase is added to phases_observed(c) when (i) at least one of the candidate's trials at that phase has reached a terminal trial status (Completed, Terminated, Withdrawn, or Suspended); (i′) at least one of the candidate's trials at that phase has a non-terminal status (Unknown, Active not recruiting, or Recruiting) but has been inactive for at least N years — defined as the latest of its completion_date or start_date being at least N years before a configured reference_date, with N = 2 years (matching ClinSR's Trial Failure Threshold; Zhou et al., Nat Commun 16:9537, 2025) and reference_date = the pipeline run date by default. This stale-status promotion compensates for pre-FDAAA-2007 registry records whose status field was never updated after registration; (ii) a Phase 4 trial satisfying either (i) or (i′) has been observed (implying the program reached Approval); or (iii) a post-clinical terminal event has been recorded — an Approved outcome (adds Approval) or a Commercialized outcome (adds Approval and Market).

  • phases_advanced(c) ⊇ phases_observed(c) — the set of phases for which there is advancement evidence, which is a superset of phases_observed(c) that additionally admits (i) any trial of any status at a given phase (so a started-but-still-active Phase 2 trial is sufficient evidence that the candidate advanced past Phase 1) and (ii) a FAILED_PHASE_N adjudicator verdict (which credits advancement to Phase N but deliberately does not add Phase N to the cohort set, since an LLM failure verdict without terminal trial evidence at that phase would otherwise pad the Phase N denominator with uncorroborated failures).

The phase-transition success rate for a transition from phase X to phase Y, evaluated over a set C of candidates, is then:

  TR(X → Y) = | { c ∈ C : X ∈ phases_observed(c) ∧ phases_advanced(c) ∩ L_X ≠ ∅ } | / | { c ∈ C : X ∈ phases_observed(c) } |

where L_X denotes the set of phases strictly later than X in the canonical order {Phase 1 < Phase 2 < Phase 3 < Approval < Market}. Equivalently, a candidate contributes to the denominator of TR(X → Y) iff it has terminal evidence at X, and contributes to the numerator iff it additionally has any evidence (terminal or non-terminal) of advancement beyond X. A configurable back-propagation rule (back_propagate_approval, ClinSR-aligned default True) then extends phases_observed(c) and phases_advanced(c) downward so that every phase at or below the candidate's highest already-observed cohort phase is included in both sets. For example, a Commercialized drug with terminal Phase 3 trial evidence is credited to Phase 1, Phase 2, and Phase 3 denominators in addition to Approval and Market. This is a deliberate departure from strict forward-looking semantics: it compensates for the well-documented pre-FDAAA-2007 registry gap in which early-phase trials for programs that reached approval are frequently missing from ClinicalTrials.gov, which would otherwise systematically deflate early-phase denominators for approved programs. Setting back_propagate_approval=False restores strict forward-looking behavior, in which Approval is not credited to earlier clinical phases when the corresponding trials are absent.
Drug modality and therapeutic area are classified into predefined taxonomies (see Supplementary Methods).
Each candidate is assigned one of seven outcome categories: Failed Phase 1, Failed Phase 2, or Failed Phase 3 (indicating that development was halted at or before the respective phase), Approved (regulatory approval granted), Commercialized (marketed product, distinct from Approved in that evidence of post-approval commercial launch exists), Ongoing (active development with no terminal event), or Unknown (insufficient evidence to determine status). Ongoing and Unknown outcomes never contribute entries to phases_observed by themselves, so candidates whose only signal is an Ongoing or Unknown verdict — with no terminal trial status and no Phase 4 or regulatory evidence — fall out of both the numerator and the denominator of every transition rate.
Data Sources and Trial Selection
Clinical trial records are obtained from ClinicalTrials.gov via the Aggregate Analysis of ClinicalTrials.gov (AACT) PostgreSQL mirror maintained by the Clinical Trials Transformation Initiative [source]. Trials are restricted to interventional studies with drug-type interventions; device, behavioral, and other non-drug intervention types are excluded. Healthy-volunteer studies, identified by case-insensitive matching of word-boundary "healthy" (optionally followed by volunteer / subject / participant / adult) in the indication field, are removed post-query. Rows whose intervention or indication field contains "placebo" (case-insensitive) are likewise removed. An optional pickle cache (aact_cache.pkl by default, enabled via --use-ct-cache) stores raw AACT query results on disk and is reused across runs to avoid repeated database round-trips; the cache is disabled by default.
Each study with M drug interventions and N condition indications undergoes M×N expansion, yielding up to M×N raw trial records — one per unique (drug, condition) pair. This expansion treats each drug-condition pairing as an independent unit of analysis, consistent with the drug-indication pair convention adopted in prior work (Thomas et al. 2016; Hay et al. 2014; Wong et al. 2019). Phase values are normalized using a deterministic mapping in which combined phases (e.g., "Phase 1/Phase 2") are assigned to the higher constituent phase (Wong et al. 2019); recognized values are Phase 1, Phase 2, Phase 3, Phase 4, N/A, and Unknown. Trial statuses are consolidated into seven canonical categories: Recruiting (which also absorbs Not Yet Recruiting and Enrolling by Invitation), Completed, Terminated, Withdrawn, Active Not Recruiting, Suspended, and Unknown. Of these, Completed, Terminated, Withdrawn, and Suspended are treated as terminal statuses for cohort-membership purposes in the transition-rate computation.

An optional single-arm filter restricts the ingested rows to studies with exactly one unique intervention and one unique condition, dropping basket trials (one intervention, multiple conditions) and umbrella trials (multiple interventions, one condition). This filter is off by default. Regardless of whether the filter is applied, every trial is classified as single-arm or not, and for single-arm trials, primary-outcome p-values and associated statistical parameters (statistical method, effect size, 95% confidence interval) are retrieved from the AACT outcome_analyses table and attached to the trial record for downstream inconsistency flagging (Section 3).
DrugBank serves as an auxiliary normalization layer for canonical drug identity resolution, enabling deduplication of candidates that refer to the same active ingredient under different trade names or salt forms. OpenFDA is a primary input to the fda_timeline outcome adjudicator, which reconstructs per-drug regulatory histories from ORIG and SUPPL submission letters and checks NDC commercial status; under the llm_direct adjudicator used for this report, OpenFDA and Drugs@FDA records contribute only indirectly, as the cross-adjudicator knowledge cache allows side-by-side reporting of cached fda_timeline verdicts alongside llm_direct verdicts.
Candidate Clustering and Deduplication
The clustering stage aggregates raw trial records into unique drug-indication candidates using a hybrid strategy that prioritizes Medical Subject Heading (MeSH) descriptors when available and falls back to normalized free-text matching otherwise. When MeSH terms are present, clustering keys are constructed by independently sorting and concatenating the MeSH intervention terms and MeSH condition terms for each trial. Two trials with identical MeSH-derived keys are assigned to the same candidate cluster. When MeSH terms are absent, keys are derived from normalized free-text drug and indication names (Unicode-normalized, lower-cased, with salt-suffix tokens stripped). This approach produces deterministic, vocabulary-controlled keys that are robust to variation in free-text naming.
Following initial clustering, a second deduplication pass leverages drug-identity signals beyond the initial clustering key. A DrugBank identifier is assigned to each candidate via the two-level canonical-name lookup described in Supplementary Methods, optionally augmented by a DrugBank-derived synonyms table (drugbank_synonyms.csv) that maps internal codenames to canonical INNs. Candidates are then re-merged via a union-find (disjoint-set) procedure over alias sets. For each eligible candidate we construct a drug-alias set, drawn from {DrugBank ID, canonical MeSH intervention term, normalized drug name, synonym-recovered canonical name}, and an indication-alias set, drawn from {canonical MeSH condition term, normalized indication name}, retaining only those tier values that are actually populated for the candidate. Alias values are namespace-tagged by their tier (e.g., ("db", DB00030), ("mesh", insulin), ("name", humulin), ("syn", semaglutide)) so that accidental string collisions across tiers cannot force false merges. Two candidates are placed in the same final cluster whenever they agree on any one drug alias and any one indication alias, and the relation is taken to its transitive closure: if candidate A shares a drug alias with B and B shares a different drug alias (or any indication alias) with C, A, B, and C all land in the same final cluster. The pipeline default (drop_unmatched_drugbank=False, reinforced at the CLI by --keep-unmatched-drugbank and used for this report) retains candidates that lack both a DrugBank ID and a MeSH intervention term, which is ClinSR-aligned and prevents novel biologics, early-stage peptides, and codename-only compounds from being silently dropped; flipping the flag to True restores the stricter legacy behavior of dropping candidates with no identifier-class drug signal. This pass corrects for cases where the initial clustering assigned the same active pharmaceutical ingredient to separate candidates due to naming variation that survived MeSH-based grouping — including cases where a pair agrees on a non-canonical alias that a single-priority rule would have ignored. Each final candidate record contains a unique identifier, canonical drug and indication names, the set of constituent trial identifiers, all sponsors, the highest clinical phase reached, earliest trial start date, latest trial completion date, DrugBank identifier where matched, MeSH intervention and condition terms, MeSH condition tree numbers, and any attached single-arm primary-outcome p-values.
The pipeline also exposes a post-clustering deterministic sampling knob (--max-candidates N --sample-seed S) that, after clustering and any optional year-range filtering, draws a reproducible random sample of N candidates via a fresh random.Random(S) instance and prunes the trial table to the union of those candidates' constituent trials so that each sampled candidate retains its full trial set. This is distinct from the raw-ingestion cap (--max-trials N), which enforces a SQL LIMIT on the AACT fetch and can leave candidates with only a partial trial subset after M×N expansion; --max-trials is appropriate for development iteration, whereas --max-candidates is the analysis-safe sampling primitive. The target run used --max-trials 76000 and no post-clustering sampling.
LLM-Assisted Classification and Adjudication
Two pipeline stages (modality/disease classification and outcome adjudication) require judgments that cannot be reliably derived from deterministic joins against structured databases alone. For these tasks, we employ large language models (LLMs) as one component of a reproducible decision system that combines deterministic preprocessing, structured prompting, tiered model routing, and persistent result caching. The two stages share a common knowledge cache and, when --all-modalities is active (as in the target run), execute concurrently on separate threads; in the default peptide-only mode, classification runs first, the candidate set is filtered to peptides, and adjudication runs only on the filtered subset to conserve LLM cost.
Disease area resolution is performed deterministically whenever possible, using a plurality vote over MeSH condition tree-number prefixes: each trial contributes its C-branch and F-branch tree numbers to the candidate, and the prefix-to-area lookup (Supplementary Methods) returns the bucket with the highest vote count, falling back to the LLM only when no tree numbers map to a named bucket or the vote ties between two named buckets. When the MeSH resolution succeeds, it overrides any LLM-produced disease area even on a cache hit, as the deterministic signal is stronger. Modality classification has no deterministic analogue and is always resolved by the LLM (or via cache) from a structured prompt containing the drug name and indication only. The classification prompt distinguishes 17 modality classes (peptide, small_molecule, protac_degrader, radioligand_therapy, monoclonal_antibody, checkpoint_inhibitor, bispecific_antibody, adc, fusion_protein, sirna, antisense, mrna_therapeutic, cell_therapy_engineered, cell_therapy_non_engineered, gene_therapy, vaccine) plus unknown, with explicit priority rules to break ties among overlapping categories: radioisotope in the drug name forces radioligand_therapy over peptide/antibody/small_molecule; an antibody carrying a cytotoxic payload forces adc over monoclonal_antibody; any antibody targeting an immune checkpoint (PD-1/PD-L1/CTLA-4/LAG-3/TIGIT/TIM-3) forces checkpoint_inhibitor over monoclonal_antibody or bispecific_antibody; a genetically modified cell product forces cell_therapy_engineered over gene_therapy; mRNA against an infectious pathogen routes to vaccine while mRNA for other indications routes to mrna_therapeutic; and induced protein-degradation mechanisms force protac_degrader over small_molecule.
Outcome adjudication has two interchangeable back-ends that emit the same CandidateOutcomeRecord schema, selected per run via --adjudication-method. Under llm_direct (used for this report), development status is determined by a combination of deterministic shortcuts and LLM evaluation. The deterministic shortcut fires when (i) every trial associated with the candidate has a terminal failure status (Terminated or Withdrawn) and (ii) the candidate's highest recorded phase is Phase 1, Phase 2, or Phase 3; in that case the candidate is assigned the corresponding FAILED_PHASE_N outcome with HIGH confidence and no LLM call is made. For all remaining candidates, the LLM receives enriched context including the drug and indication names, highest phase reached, sponsor list, earliest trial start and latest trial completion dates, a count of trials per normalized status, and the number of constituent trials, so the model grounds its reasoning in observed registry state rather than training-data recall.
Under fda_timeline (the library default, not used in this report), each candidate's drug is resolved to an FDA timeline reconstructed from openFDA ORIG and SUPPL submission letters; an LLM extracts and matches the trial indication against the approved indication list per submission, and a separate NDC query determines whether the drug is currently commercialized. If the trial indication matches an approved indication and active NDC records exist, the candidate is assigned Commercialized; with approval but no active NDC the candidate is Approved; if no matching approval is found and the candidate's trial activity is older than fda_failure_window_days (730 days by default) the candidate is assigned FAILED_PHASE_N at the highest recorded phase; otherwise it is Ongoing. FDA HTTP responses are cached on disk under .fda_cache/, and the LLM backend is independently configurable via --fda-llm-backend, with the openai_compat default targeting a local Ollama endpoint (http://localhost:11434/v1) serving qwen2.5:14b-instruct; --fda-llm-backend anthropic opts into Claude Sonnet for this stage instead. Because both adjudicators write to the shared persistent knowledge cache, the reporting stage can surface cached llm_direct and fda_timeline verdicts side by side in the candidate-summary CSV regardless of which adjudicator ran for the current invocation.
Tiered model routing balances classification accuracy and computational cost for the Anthropic-backed stages (modality/disease classification and llm_direct adjudication). Each batch is first evaluated on Claude Sonnet 4.6 (identifier claude-sonnet-4-6); any candidate whose response is missing, has LOW confidence, or returns an UNKNOWN / "unknown" value for the stage's target field is re-evaluated in a second pass on Claude Opus 4.6 (identifier claude-opus-4-6), and the Opus response replaces the Sonnet response for those candidates. All LLM calls use temperature 0.0. Classification runs up to 50 candidates per batched prompt and adjudication runs up to 25 per prompt, in both cases to amortize system-prompt overhead. Run-to-run reproducibility is ensured through a persistent SHA-256-keyed SQLite knowledge cache; classification results are keyed by (normalized drug name, indication) and adjudication results by (normalized drug name, indication, highest phase reached), so a change in the observed highest phase invalidates a stale adjudication entry while leaving the classification entry intact. The fda_timeline adjudicator writes its LLM intermediate JSON into a separate cache table (llm_json_cache) keyed by prompt-content hash, so FDA-stage caching is orthogonal to the llm_direct adjudication cache and both coexist for downstream comparison.
Transition Rate Computation
Phase-transition success rates are computed for four sequential transitions: Phase 1 to Phase 2, Phase 2 to Phase 3, Phase 3 to Approval, and Approval to Market. For each candidate we first materialize phases_observed and phases_advanced by scanning (i) the candidate's constituent trials — each trial contributes its phase to phases_advanced, and additionally to phases_observed if its status is terminal; Phase 4 trials are mapped to Approval for both sets; and (ii) the adjudicated outcome record — FAILED_PHASE_N verdicts add Phase N to phases_advanced only, Approved outcomes add Approval to both sets, and Commercialized outcomes add both Approval and Market to both sets. The transition rate for X → Y over a set C of candidates is then computed as defined in the Definitions section: the denominator is the number of candidates in C with X in phases_observed, and the numerator is the subset of those whose phases_advanced contains any phase strictly later than X.
Transition rates are computed at four levels of stratification: (1) overall, across all candidates; (2) stratified by drug modality; (3) stratified by therapeutic area; and (4) cross-stratified by modality and therapeutic area. The cross-stratification enables identification of modality-specific translational patterns within individual disease areas and vice versa. In addition, a time-period analysis partitions candidates by the year of their earliest trial start date into three configurable cohorts — 1962–2000, 2000–2006, and 2007–2026 in the default configuration — and recomputes the overall and per-disease-area transition rates within each cohort using the identical forward-looking logic, enabling comparison of translational performance across eras. The cohort list is overridable per run via the time_periods field of PipelineConfig.
Average phase duration is estimated for each transition. For clinical-phase transitions, duration is computed as the mean elapsed time from trial start date to primary completion date across the candidate's constituent trials at each phase, restricted to trials with positive (start, completion) duration. For the Approval to Market transition, duration is computed across candidates as the mean elapsed time from approval date to commercialization date, where both dates are populated by the outcome adjudicator.
Statistical Methods
All transition rates are accompanied by 95% Wilson score confidence intervals, which provide descriptive binomial uncertainty around observed proportions (see Supplementary Methods for formulation). These intervals are framed as descriptive measures of uncertainty in the analyzed dataset rather than population-level inferential guarantees.
The overall likelihood of approval (LOA) from Phase 1 to Market is computed as the product of the four sequential transition rates.

5. Limitations
Several limitations qualify the interpretation of our results.
5.1 Reconciling Three Different Absolute LOA Estimates
The most prominent calibration issue is that three independent estimates of the Phase 1 LOA from public-data analyses now exist in the literature: Hay et al. (2014) report ~10.4% from the BioMedTracker corpus for 2003–2011; Zhou et al. (2025) report a recent stabilization around ~5% from ClinicalTrials.gov; and our pipeline reports 28.8% across its full multi-decade window. These figures differ by roughly a factor of six between the lowest and highest. We do not view this as substantive disagreement about the underlying landscape but as a consequence of differing methodological choices, of which the most important are:
Time window. Our pipeline aggregates candidates across the full multi-decade historical window spanned by the ingested AACT records (by default partitioned into 1962–2000, 2000–2006, and 2007–2026 cohorts for time-period analysis), while Zhou et al.'s headline ~5% figure refers to recent rolling nine-year windows after a documented secular decline. Hay et al.'s ~10% applies to 2003–2011. A fair side-by-side comparison would require restricting our pipeline to matching windows, which we have not yet done in this analysis.
Candidate definition and outcome treatment. Our pipeline credits candidates at the Approval or Market level when post-clinical outcomes are unambiguous, even if trial-phase metadata is stale, and admits started-but-not-yet-terminal late-phase trials as advancement evidence for earlier transitions via the phases_advanced superset. Zhou et al. and Hay et al. apply different rules for treating ongoing and unresolved programs. The combination of our forward-looking cohort definition (in which candidates without terminal trial evidence at a phase are absent from both the numerator and the denominator at that phase) and the post-clinical outcome promotion rule will tend to inflate observed transition rates relative to approaches that treat unresolved programs as implicit failures or that anchor on the highest registry-recorded phase.
Source corpus. Hay et al. used BioMedTracker, a commercial database. Our pipeline and Zhou et al. both use ClinicalTrials.gov, but the specific ingestion query, exclusion criteria, and clustering logic differ. Zhou et al. successfully reproduced Hay et al.'s 2003–2011 numbers within ~5% relative difference using harmonized definitions, demonstrating that methodology, not data source, drives the headline gap.
Because of this calibration uncertainty, we have framed our substantive claims in relative terms throughout, and we caution against direct numerical comparison of our absolute rates to those of prior studies. A planned follow-up will restrict our pipeline to the 2003–2011 and 2015–2023 windows used by Hay et al. and Zhou et al. respectively, with harmonized candidate definitions, to enable direct apples-to-apples comparison.
5.2 Other Limitations
The pipeline relies on ClinicalTrials.gov as its primary data source. Trials not registered in ClinicalTrials.gov — including some non-U.S. development programs and historical trials predating registry requirements — are systematically underrepresented. This may bias the dataset toward U.S.-centric and post-2000 development activity, despite the formally longer historical window represented in the AACT records. A related registry-quality issue is that trials registered before the FDA Amendments Act of 2007 often have their status field frozen at Unknown, Active not recruiting, or Recruiting indefinitely because sponsors were not required to update records; the stale-status promotion rule described in the Definitions section mitigates this by treating such trials as cohort-eligible once their latest activity date is at least N years in the past (N = 2 by default, matching ClinSR's 2-year Trial Failure Threshold), bringing cohort membership closer to the phase-plus-date logic used by ClinSR and BIO/QLS. The residual bias is in the opposite direction: trials registered after 2007 with genuinely active non-terminal statuses (e.g., a still-recruiting Phase 2) remain excluded from cohort membership, as they should be, since the program has not yet reached a resolved state at that phase.
Classification of modality and disease area, and adjudication of outcomes, depend in part on large language model judgments. While we mitigate this through deterministic preprocessing, structured prompting, tiered model routing, persistent caching, and a five-layer validation framework with perturbation analysis, residual classification error cannot be excluded and will propagate into the stratified rates. The use of LLMs introduces a class of failure modes — including taxonomy drift, prompt sensitivity, and model-version dependence — that rule-based pipelines such as ClinSR do not face. We mitigate version dependence through persistent caching and full version pinning of all model calls.
The analysis is observational and historical. The relative orderings we report describe the empirical track record of past development programs and should not be interpreted as forward-looking forecasts. Modality- and area-specific success rates can shift as the underlying scientific and regulatory landscape evolves; Zhou et al.'s temporal analysis demonstrates substantial drift over the 2001–2023 period, and our results should be re-computed periodically rather than treated as fixed parameters.
The timeline-LOA association reported in Section 3.6 is correlational. We do not claim that shorter timelines cause higher success rates or vice versa; both are likely jointly determined by features of the underlying biology, endpoint structure, and regulatory pathway in each therapeutic area.


Supplementary Methods
Taxonomies
Drug modality is classified into one of 16 named categories (peptide; small_molecule; protac_degrader covering PROTACs, molecular glues, and CELMoDs; radioligand_therapy covering radiopharmaceuticals delivering therapeutic isotopes such as Lu-177, Ac-225, I-131, Y-90; monoclonal_antibody; checkpoint_inhibitor covering any antibody targeting PD-1/PD-L1/CTLA-4/LAG-3/TIGIT/TIM-3; bispecific_antibody including BiTEs and T-cell engagers; adc for antibody-drug conjugates; fusion_protein including receptor-Fc traps; sirna; antisense; mrna_therapeutic covering mRNA encoding a therapeutic protein for non-vaccine indications, including personalized cancer neoantigen vaccines; cell_therapy_engineered for genetically modified cells such as CAR-T / TCR-T / CAR-NK; cell_therapy_non_engineered for unmodified cell products such as MSCs, TILs, cord blood, and dendritic cell products; gene_therapy; and vaccine for prophylactic or therapeutic immunization against infectious pathogens, including mRNA vaccines for infectious diseases) plus unknown when classification confidence is insufficient. Overlapping categories are resolved by explicit priority rules (see main text: radioisotope → radioligand_therapy; antibody + cytotoxic payload → adc; immune-checkpoint target → checkpoint_inhibitor; engineered cells → cell_therapy_engineered over gene_therapy; infectious-pathogen mRNA → vaccine, other mRNA → mrna_therapeutic; induced protein degradation → protac_degrader over small_molecule).
Therapeutic area is classified into one of 13 named categories (oncology, cardiovascular, metabolic, neurology, autoimmune, infectious disease, respiratory, hematology, ophthalmology, psychiatry, gastroenterology, endocrine, and urology) plus a residual "other" category and unknown.
Data Extraction Details
The pipeline queries the AACT ctgov schema, joining the studies, interventions, conditions, browse_interventions, browse_conditions, sponsors, and mesh_terms tables; for single-arm trials it additionally joins outcomes and outcome_analyses to retrieve primary-outcome p-values and associated statistical parameters. Non-drug intervention types are excluded via upper(i.intervention_type) = 'DRUG', and interventional studies are selected via upper(s.study_type) = 'INTERVENTIONAL'. Rows whose indication field contains the substring "healthy" (case-insensitive) are dropped post-query to remove healthy-volunteer studies.
MeSH Tree–to–Disease Area Mapping
Disease-area resolution from MeSH condition tree numbers uses the first three characters of each tree number as a prefix key, with the following mapping: C01/C02/C03 → infectious disease; C04 → oncology; C06 → gastroenterology; C08 → respiratory; C10 → neurology; C11 → ophthalmology; C12 → urology; C14 → cardiovascular; C15 → hematology; C18 → metabolic; C19 → endocrine; C20 → autoimmune; F03 → psychiatry. Tree numbers that do not match any listed prefix are treated as "other"; if every prefix fails to map, the candidate is assigned "other" outright. A plurality vote across all tree numbers on the candidate's constituent trials selects the winning bucket; a tie between the top two named buckets falls back to the LLM for disease-area determination.
Drug Name Canonicalization
Drug names undergo a 10-step canonicalization procedure before matching: (1) Unicode NFKD normalization with diacritic stripping and µ → u; (2) removal of parenthetical, bracketed, and braced descriptors; (3) lower-casing; (4) conversion of separator characters (/, comma, underscore, semicolon, colon, hyphen, en-dash, em-dash) to spaces; (5) removal of quote characters; (6) removal of remaining punctuation; (7) normalization of radioisotope formats (e.g., "177 lu" → "177lu"); (8) removal of non-identity tokens (placebo, sham, oral, injection, extended, release, and similar formulation / route / presentation / regimen words); (9) Roman numeral normalization (i, ii, iii, iv, v → 1, 2, 3, 4, 5); (10) whitespace collapse.
Canonicalized drug names are matched against a pre-processed DrugBank approvals dataset via two-level lookup: first by exact canonical-name match against the deduplicated query_norm column, then by first-word fallback for multi-word names (the first token of the canonical name is looked up against the same column). The DrugBank approvals table is deduplicated per key by retaining, for each duplicated key, the row with the largest count of non-null columns, ensuring that the most complete record wins when multiple candidates share a canonical name.
LLM Implementation Details
Classification is performed in batches of up to 50 candidates per prompt; llm_direct adjudication is performed in batches of up to 25 per prompt. Prompts include system instructions defining the output schema, the full modality and disease-area taxonomies, modality definitions (e.g., peptide = chain of 2–50 amino acids including cyclic, stapled, and peptide hormones/analogs; small_molecule = chemically synthesized compound typically <900 Da, excluding PROTACs/degraders and radioligand therapies), confidence requirements, the priority rules enumerated above, and per-candidate field blocks numbered by 1-based index. The model returns a JSON array with one element per candidate, each containing the candidate_index, structured outputs for the target fields, per-field confidence labels (HIGH / MEDIUM / LOW), and a short reasoning string. Confidence labels are mapped internally to numeric scores (HIGH → 1.0, MEDIUM → 0.5, LOW → 0.25) for downstream use.
The llm_direct adjudication prompt additionally receives per-trial status counts, the highest phase reached, sponsor list, trial count, earliest start date, and latest completion date, so the model grounds its verdict in observable registry state. LLM-returned disease-area strings are normalized through a taxonomy-alias map (e.g., immunology → autoimmune, allergy → autoimmune, endocrinology → endocrine, hepatology → gastroenterology) and then collapsed into the BIO/QLS-aligned 13-category taxonomy plus "other" and "unknown" buckets; any value that still fails to map is coerced to "unknown".
Tiered routing escalates any result with LOW confidence, a missing response, or an UNKNOWN / "unknown" value for the target field from the base model (Claude Sonnet 4.6, identifier claude-sonnet-4-6) to a higher-capability model (Claude Opus 4.6, identifier claude-opus-4-6); only the subset of escalated candidates is re-submitted, and returned Opus results overwrite the corresponding Sonnet results before final parsing. All LLM calls use temperature 0.0 with the Anthropic ephemeral prompt cache enabled on the system prompt to reduce repeated-input cost.
The fda_timeline adjudicator uses a separate LLM stack, structured so that raw regulatory-document text is not passed directly to the model. A pre-LLM extraction step (pipeline/fda/section_extract.py) narrows label and letter inputs to roughly 1.5–3 kb of the most relevant indication-bearing passages before invocation, which restores most of the quality lost when switching from a 32B to a 14B local model. The LLM backend is swappable via --fda-llm-backend {openai_compat, anthropic}, with the default openai_compat backend pointing at a local Ollama endpoint (http://localhost:11434/v1) serving qwen2.5:14b-instruct; passing --fda-llm-model qwen2.5:32b-instruct opts into the larger model, and passing --fda-llm-backend anthropic opts into Claude Sonnet for this stage only. The --fda-adjudication-workers, --fda-llm-timeout, and --fda-http-timeout flags govern candidate-level parallelism and per-call timeouts for this stage; per-drug timelines are deduplicated under a lock so candidates sharing a drug do not redundantly hit openFDA. Local-model calls are recorded at zero token cost in the cost ledger. This flag scope is confined to fda_timeline: classification and llm_direct adjudication continue to run on Anthropic regardless of --fda-llm-backend.
Peptide-Only Mode
When peptide_only mode is enabled (the default for the peptide report), the pipeline classifies the full candidate set first, then filters to candidates whose drug_modality is "peptide", and finally runs outcome adjudication only on that filtered subset. Non-peptide candidates are retained for modality reporting but skip the adjudication-LLM step entirely, substantially reducing total LLM cost when only peptides are of interest. The report accompanying this paper was produced with --all-modalities, which disables the peptide pre-filter and runs classification and llm_direct adjudication concurrently over the full candidate set.
Caching and Reproducibility
Run-to-run reproducibility is ensured by a SHA-256-keyed SQLite knowledge cache (knowledge_cache.db) that persists all classification and adjudication results across runs. Classification entries are keyed by SHA-256 of "<lower-cased drug name>|<lower-cased indication>"; llm_direct adjudication entries are keyed by SHA-256 of "<lower-cased drug name>|<lower-cased indication>|<lower-cased highest phase>", so a change in the observed highest phase invalidates a prior adjudication entry while leaving the associated classification entry intact. fda_timeline adjudicator LLM calls (indication matching, label extraction) persist to a parallel llm_json_cache table keyed by prompt-content hash, so fda_timeline and llm_direct verdicts coexist for the same (drug, indication) pair without either overwriting the other; the reporting stage takes advantage of this by surfacing both cached verdicts side by side in the candidate-summary CSV alongside an outcomes_agree flag, even when only one adjudicator was run for the current invocation. The knowledge cache is opened in WAL (Write-Ahead Logging) mode and uses per-thread connections, allowing the parallel classification and adjudication stages to read and write concurrently without lock contention.
A separate AACT fetch cache (aact_cache.pkl) is controlled by --use-ct-cache; when enabled, raw trial ingestion results are serialized to disk and reused on subsequent runs to skip the AACT PostgreSQL round-trip entirely. This cache is disabled by default but was enabled for the target run. It is independent of the LLM knowledge cache and of the .fda_cache/ directory used by the fda_timeline adjudicator to cache openFDA HTTP responses.
Statistical Formulation
Wilson score intervals for a binomial proportion k/n are computed at the 95% confidence level (z = 1.959963984540054) as:

  center = (p̂ + z²/(2n)) / (1 + z²/n)
  halfwidth = (z · √( p̂(1 − p̂)/n + z²/(4n²) )) / (1 + z²/n)
  CI₉₅ = [ max(0, center − halfwidth), min(1, center + halfwidth) ]

where p̂ = k/n. Intervals are undefined (returned as NaN) when n = 0 or when either k or n is non-finite. Approximate confidence bounds for the LOA from phase X are computed as the product of the Wilson lower (respectively upper) bounds across the four sequential transitions, which is an approximation that ignores the joint distribution of the four transition estimates.
Target-Run Configuration
The report bundled with this paper was produced from the project root with:

  uv run python run_pipeline.py --output ../docs --max-trials 76000 \
    --drugbank-csv ../drugbank_approvals.csv --keep-unmatched-drugbank \
    --all-modalities --use-ct-cache --adjudication-method llm_direct

Resolved options: AACT data source (default); raw-ingestion cap of 76000 rows with no post-clustering candidate sampling (no --max-candidates); hybrid MeSH-plus-text clustering (default); DrugBank normalization enabled with unmatched candidates retained (drop_unmatched_drugbank=False); full-modality pipeline with no peptide pre-filter and concurrent classification + adjudication (peptide_only_report=False); llm_direct outcome adjudication backed by the Anthropic tiered router (Claude Sonnet 4.6 → Claude Opus 4.6); AACT pickle cache reuse enabled (aact_cache.pkl); stale_trial_cutoff_years=2.0 and back_propagate_approval=True (ClinSR-aligned defaults); time-period cohorts (1962, 2000), (2000, 2006), (2007, 2026); HTML-only report format.
